# Use Nginx with a manual NetBird deployment

This guide installs Nginx on the NetBird host, obtains a Let's Encrypt certificate with Certbot, and routes either NetBird layout. It also lists the upstream changes for Nginx running in Docker.

Prepare NetBird first:

- **Combined container:** follow steps 1 to 4 of [Manual setup](/selfhosted/manual-setup) and create the Compose file from [Use another reverse proxy](/selfhosted/manual-setup#use-another-reverse-proxy).
- **Multi-container:** follow [Manual multi-container setup](/selfhosted/manual-setup/multi-container) through step 7.

Both Compose files publish the NetBird backends on `127.0.0.1` for an Nginx installed on the host.

## How Nginx routes NetBird

Nginx terminates TLS and accepts HTTP/2 from NetBird clients. It sends native gRPC to an h2c backend with `grpc_pass`, sends Relay and fallback paths with WebSocket upgrade headers, and sends the Dashboard to a catch-all HTTP upstream.

UDP 3478 bypasses Nginx and must remain published directly from `netbird-server` or `relay`.

The configurations route `/management.ProxyService/` for completeness, but the [NetBird Proxy](/manage/reverse-proxy) feature does not work behind Nginx. It needs TLS passthrough, which only Traefik provides; see [Enable Reverse Proxy](/selfhosted/migration/enable-reverse-proxy).

<Warning>
Do not replace `grpc_pass` with `proxy_pass` for native gRPC paths. Do not send gRPC paths through the Dashboard catch-all. Either mistake can leave the Dashboard working while every client fails to connect.
</Warning>

## 1. Configure trusted proxy addresses

When Nginx is installed on the host and connects through Docker-published loopback ports, NetBird sees the source as the private bridge gateway used by these manual guides: `172.30.0.1`.

Combined `config.yaml`:

```yaml
server:
  reverseProxy:
    trustedHTTPProxies:
      - "172.30.0.1/32"
    trustedPeers:
      - "172.30.0.1/32"
```

Multi-container `management.json`:

```json
{
  "ReverseProxy": {
    "TrustedHTTPProxies": ["172.30.0.1/32"],
    "TrustedHTTPProxiesCount": 0,
    "TrustedPeers": ["172.30.0.1/32"]
  }
}
```

If Nginx runs in Docker at the fixed address `172.30.0.10`, trust `172.30.0.10/32` instead. Never trust `0.0.0.0/0`.

## 2. Install Nginx and Certbot

On Ubuntu or Debian:

```bash
sudo apt update
sudo apt install nginx certbot python3-certbot-nginx
sudo systemctl enable --now nginx
```

Ensure no other process owns TCP 80 or 443:

```bash
sudo ss -lntp | grep -E ':(80|443)\b' || true
```

## 3. Bootstrap the certificate

Create a temporary HTTP-only server. Replace the hostname first:

```bash
NETBIRD_DOMAIN="netbird.example.com"

sudo tee /etc/nginx/sites-available/netbird >/dev/null <<EOF
server {
    listen 80;
    listen [::]:80;
    server_name ${NETBIRD_DOMAIN};

    location / {
        return 200 'NetBird TLS bootstrap';
        add_header Content-Type text/plain;
    }
}
EOF

sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sfn /etc/nginx/sites-available/netbird /etc/nginx/sites-enabled/netbird
sudo nginx -t
sudo systemctl reload nginx
```

Request the certificate:

```bash
sudo certbot certonly --nginx -d "$NETBIRD_DOMAIN" \
  --deploy-hook "systemctl reload nginx"
```

Certbot installs a renewal timer. The deploy hook reloads Nginx after each renewal, so it serves the new certificate instead of the one it loaded at startup. Test the complete renewal path after the final Nginx configuration is active:

```bash
sudo certbot renew --dry-run
```

<Note>
The examples use `listen 443 ssl http2;`, which works on old and current Nginx releases alike, including the packaged versions in Ubuntu 22.04 and 24.04, Debian 12, and Rocky Linux 9. On Nginx 1.25.1 and newer, `nginx -t` prints a deprecation warning for it; see [Troubleshooting Nginx](#troubleshooting-nginx) if you want to switch to `http2 on;`.
</Note>

## Combined container layout

The Compose file from [Use another reverse proxy](/selfhosted/manual-setup#use-another-reverse-proxy) publishes the Dashboard on `127.0.0.1:8080` and `netbird-server` on `127.0.0.1:8081`, and `config.yaml` must trust `172.30.0.1/32`.

Replace `/etc/nginx/sites-available/netbird` with:

```nginx
upstream netbird_dashboard {
    server 127.0.0.1:8080;
    keepalive 10;
}

upstream netbird_server {
    server 127.0.0.1:8081;
}

server {
    listen 80;
    listen [::]:80;
    server_name netbird.example.com;

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name netbird.example.com;

    ssl_certificate /etc/letsencrypt/live/netbird.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/netbird.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_header_timeout 1d;
    client_body_timeout 1d;

    # Overwrite the client's own X-Forwarded-For on gRPC requests.
    grpc_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    # Relay and gRPC-over-WebSocket fallback paths.
    location ~ ^/(relay|ws-proxy/) {
        proxy_pass http://netbird_server;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_read_timeout 1d;
    }

    # Native Signal, Management, and optional NetBird Proxy gRPC.
    location ~ ^/(signalexchange\.SignalExchange|management\.(ManagementService|ProxyService))/ {
        grpc_pass grpc://netbird_server;
        grpc_read_timeout 1d;
        grpc_send_timeout 1d;
        grpc_socket_keepalive on;
    }

    # REST API and embedded identity provider.
    location ~ ^/(api|oauth2)/ {
        proxy_pass http://netbird_server;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
    }

    # Dashboard catch-all must remain last and least specific.
    location / {
        proxy_pass http://netbird_dashboard;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
    }
}
```

The port 80 redirect sits inside `location /` rather than at server level, so an ACME client such as acme.sh can add a more specific `/.well-known/acme-challenge/` location that still answers over HTTP.

A `location` that sets any `proxy_set_header` does not inherit the ones in `server`, so each HTTP location sets the forwarding headers itself. The gRPC locations set no `grpc_set_header` of their own and inherit the server-level one.

Replace every `netbird.example.com` occurrence, then validate and reload:

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo certbot renew --dry-run
```

## Multi-container layout

The Compose file from [Manual multi-container setup](/selfhosted/manual-setup/multi-container) publishes all private backends on loopback. Set `NETBIRD_TRUSTED_PROXY=172.30.0.1/32` in its step 3. Use this Nginx configuration:

```nginx
upstream netbird_dashboard {
    server 127.0.0.1:8080;
    keepalive 10;
}

upstream netbird_signal_grpc {
    server 127.0.0.1:10000;
}

upstream netbird_signal_http {
    server 127.0.0.1:8083;
}

upstream netbird_management {
    server 127.0.0.1:8081;
}

upstream netbird_relay {
    server 127.0.0.1:8084;
}

server {
    listen 80;
    listen [::]:80;
    server_name netbird.example.com;

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name netbird.example.com;

    ssl_certificate /etc/letsencrypt/live/netbird.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/netbird.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_header_timeout 1d;
    client_body_timeout 1d;

    # Overwrite the client's own X-Forwarded-For on gRPC requests.
    grpc_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

    location /relay {
        proxy_pass http://netbird_relay;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_read_timeout 1d;
    }

    location /ws-proxy/signal {
        proxy_pass http://netbird_signal_http;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_read_timeout 1d;

    location /signalexchange.SignalExchange/ {
        grpc_pass grpc://netbird_signal_grpc;
        grpc_read_timeout 1d;
        grpc_send_timeout 1d;
        grpc_socket_keepalive on;
    }

    location ~ ^/(api|oauth2)/ {
        proxy_pass http://netbird_management;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
    }

    location /ws-proxy/management {
        proxy_pass http://netbird_management;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_read_timeout 1d;
    }

    location ~ ^/management\.(ManagementService|ProxyService)/ {
        grpc_pass grpc://netbird_management;
        grpc_read_timeout 1d;
        grpc_send_timeout 1d;
        grpc_socket_keepalive on;
    }

    location / {
        proxy_pass http://netbird_dashboard;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
    }
}
```

Replace the hostname, then run:

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo certbot renew --dry-run
```

The `relay` service must still publish UDP 3478 directly.

## Nginx running in Docker

When Nginx runs as a container, it joins `netbird-proxy` at `172.30.0.10` and reaches NetBird by container name. Use the same configurations as above with three changes:

1. Replace each loopback upstream with the container address from the table below.
2. Set both trusted proxy lists in NetBird to `172.30.0.10/32` instead of `172.30.0.1/32`.
3. Mount the configuration and certificates into the container.



| Layout | Logical upstream | Docker upstream |
|---|---|---|
| Combined | Dashboard | `netbird-dashboard:80` |
| Combined | Server | `netbird-server:80` |
| Multi-container | Dashboard | `netbird-dashboard:80` |
| Multi-container | Signal gRPC | `netbird-signal:10000` |
| Multi-container | Signal WebSocket | `netbird-signal:80` |
| Multi-container | Management | `netbird-management:80` |
| Multi-container | Relay | `netbird-relay:80` |

If you installed Nginx on the host in step 2, stop and disable it first, because the container publishes the same ports. The certificates in `/etc/letsencrypt` stay where they are:

```bash
sudo systemctl disable --now nginx
```

A Compose file for the Nginx container, kept in its own directory beside `netbird.conf`, can look like this. It reuses the certificates Certbot keeps on the host. Start NetBird first so `netbird-proxy` exists:

```yaml
services:
  nginx:
    image: nginx:1.28
    container_name: netbird-nginx
    restart: unless-stopped
    networks:
      netbird-proxy:
        ipv4_address: 172.30.0.10
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./netbird.conf:/etc/nginx/conf.d/default.conf:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro

networks:
  netbird-proxy:
    external: true
```

Certbot's `--nginx` plugin can't reach Nginx in a container. Use the standalone authenticator instead, and let Certbot stop the container while it binds port 80. It saves the hooks and runs them again on every renewal:

```bash
sudo certbot certonly --standalone -d netbird.example.com \
  --pre-hook "docker stop netbird-nginx" \
  --post-hook "docker start netbird-nginx"
```

If you already issued the certificate with `--nginx` in step 3, add `--force-renewal`. Otherwise Certbot reports that the certificate isn't due yet and keeps the old settings, and later renewals still try to use the host Nginx.

You can remove the NetBird `127.0.0.1` port mappings once Nginx reaches the containers by name.

## Verify Nginx and NetBird

Check listeners and Nginx state:

```bash
sudo systemctl --no-pager --full status nginx
sudo ss -lntp | grep -E ':(80|443)\b'
```

From another network, verify HTTPS and OIDC:

```bash
NETBIRD_DOMAIN="netbird.example.com"

curl -fsSI "http://${NETBIRD_DOMAIN}/"
curl -fsS "https://${NETBIRD_DOMAIN}/oauth2/.well-known/openid-configuration"
```

Then run the setup-state, gRPC, and WebSocket probes from [Verify before creating the first owner](/selfhosted/external-reverse-proxy#verify-before-creating-the-first-owner). Create the first owner and enroll two clients to prove Management, Signal, and Relay work, not only the Dashboard.

## Troubleshooting Nginx

### `nginx -t` warns that the `listen ... http2` directive is deprecated

Nginx 1.25.1 and newer print `the "listen ... http2" directive is deprecated, use the "http2" directive instead`. It's a warning, and the configuration still works. To silence it, change each `listen 443 ssl http2;` line to `listen 443 ssl;` and add `http2 on;` to the server block.

### `nginx -t` fails with `unknown directive "http2"`

Your configuration uses `http2 on;`, but your Nginx is older than 1.25.1. Remove `http2 on;` and add `http2` to each 443 listener instead:

```nginx
listen 443 ssl http2;
listen [::]:443 ssl http2;
```

### The gRPC probe returns HTML

The request reached the Dashboard. Check the exact `location` expression, keep it above the catch-all, and make sure it uses `grpc_pass grpc://...`.

### WebSocket requests return `400` or disconnect

Confirm HTTP/1.1, `Upgrade`, `Connection`, and the one-day read timeout are present. Check both Nginx's error log and the target service log:

```bash
sudo tail -n 100 /var/log/nginx/error.log
docker compose logs --tail=100 netbird-server
```

For the multi-container layout, inspect `signal`, `relay`, or `management` according to the failing path.

### Certificate issuance or renewal fails

Confirm DNS points directly to this host and TCP 80 is reachable. Validate Nginx before retrying Certbot:

```bash
sudo nginx -t
sudo certbot renew --dry-run
```

### Forwarded addresses are ignored

Check the actual bridge gateway:

```bash
docker network inspect netbird-proxy \
  --format '{{(index .IPAM.Config 0).Gateway}}'
```

Use that single address with `/32` in both `trustedHTTPProxies` and `trustedPeers`, then restart the NetBird server or Management container.
