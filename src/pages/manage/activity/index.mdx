# Audit Events Logging

The Audit events logging functionality in NetBird allows you to observe and track changes to your network infrastructure.
This includes events such as when a new machine or user has joined your network, when access control policies have been modified,
and many other key network events.

## Access the Audit Events Logging View
The audit events logging feature is enabled by default for every NetBird network. In the dashboard, open **[Audit Events](https://app.netbird.io/events/audit)**. This view provides a centralized log of network events. You can use the search bar to search by activity name, and apply filters for timeframes, event types, and users.

<Note>
    The `unknown` name or `unknown@unknown.com` email address may be displayed in the activity event store if the encryption key has been corrupted or lost. This issue is most relevant for self-hosted setups. In this case, the events returned by the API could show `unknown@unknown.com` for the email address field and `unknown` for the name field.
    
    For the combined setup, the encryption key is the <b>server.store.encryptionKey</b> field in <b>config.yaml</b>. For older multi-container setups generated by the <b>configure.sh</b> script, look for the <b>DataStoreEncryptionKey</b> field in the <b>management.json</b> backup file.
</Note>

## Peer Session Events

NetBird records a **Peer connected** event (`peer.connect`) when a peer's session with the Management server starts, and a **Peer disconnected** event (`peer.disconnect`) when it ends. Events are only recorded for the peer's current session, so late updates from a session that a newer one already replaced are ignored.

Each event carries the peer's details: name, FQDN, IP address, and the connection IP with its country and city when geolocation is configured. It also includes the peer's serial number, operating system and version, hostname, and the ID of the owning user when the peer has one. Disconnect events add `session_duration`, the length of the session that just ended in seconds.

Events are attributed to the user who owns the peer. Peers added with a setup key have no owner, so their events are recorded as system events.

<Note>
    After the Management server restarts, every peer reconnects. To keep the log readable, no connect or disconnect events are recorded during a startup grace window (2 minutes by default), and no disconnect events are recorded while the server is shutting down.

    Self-hosted deployments can change the window with the `NB_PEER_SESSION_EVENTS_STARTUP_GRACE` environment variable. See [environment variables](/selfhosted/environment-variables#advanced-runtime-variables).
</Note>

## Dashboard Login Location

**Dashboard login** events record the IP address the login came from (`location_connection_ip`) and, when geolocation is configured, the country, city and geo name ID. This also applies to MCP OAuth logins.

<Note>
    Self-hosted deployments behind a reverse proxy must list the proxy in `trustedHTTPProxies`. Otherwise the recorded IP is the proxy's address. See [running NetBird behind a reverse proxy](/selfhosted/external-reverse-proxy).
</Note>

## Enable Audit Events Streaming to SIEM Systems

NetBird can stream audit events to your Security Information and Event Management (SIEM) system in real-time. With this feature enabled, you can monitor and analyze NetBird network changes within your SIEM infrastructure. Check the [integrations guide](/manage/activity/event-streaming) for more information about the supported integrations and how to enable them.
