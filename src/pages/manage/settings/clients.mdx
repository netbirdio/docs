# Client Settings

The `Clients` tab under [Settings](https://app.netbird.io/settings) holds account-wide settings that control how NetBird clients behave. Changing these settings requires a role with permission to update settings, such as `Owner` or `Admin`. Roles with read-only access to settings can view the tab, but the controls are disabled.

## Automatic Updates

Choose an update method for your clients: keep them on the latest stable release, pin them to a specific version, or disable updates. The `Force Automatic Updates` toggle installs updates in the background without user interaction.

See [Client Automatic Updates](/manage/peers/auto-update) for the full behavior, platform support, and version requirements.

## Expose Services from CLI

The `Enable Peer Expose` toggle allows peers to expose local HTTP services through the NetBird reverse proxy using the `netbird expose` command. This requires NetBird v0.66.0 or later.

When enabled, you must select at least one peer group under `Allowed peer groups`. Only peers in the selected groups can expose services.

See [Expose Services from the CLI](/manage/reverse-proxy/expose-from-cli) for command usage and examples.

## Lazy Connections

Instead of maintaining always-on connections, NetBird can activate peer connections on demand based on activity or signaling. Enable the `Enable Lazy Connections` toggle to turn this on for compatible clients. This requires NetBird client v0.50.1 or higher.

See [Lazy Connections](/manage/peers/lazy-connection) for how activation works, inactivity thresholds, and per-client overrides.

## Unique Peer Hostnames

Two machines in one account can register with the same hostname, for example similar VMs that a provisioning tool all named `laptop`. Every peer still needs its own DNS name, so by default NetBird keeps the registration and adds the last two octets of the peer's NetBird IP to its DNS name: a second `laptop` that gets the IP `100.64.12.7` becomes `laptop-12-7.netbird.cloud`. A peer renamed to a name another peer already uses as its DNS name gets the same suffix. By default, [ephemeral peers](/manage/peers/register-machines-using-setup-keys#ephemeral-peers) get the suffix even when no other peer uses their hostname.

The suffix gives each peer its own DNS name, but it also hides that two machines share a hostname. If you want such a registration to fail loudly instead, enable the `Reject Hostname Collisions` toggle under `Unique Peer Hostnames` in the `Clients` tab of [Settings](https://app.netbird.io/settings). The setting applies to the whole account and is off by default.

<p>
    <img src="/docs-static/img/manage/settings/unique-peer-hostnames.png" alt="Unique Peer Hostnames section of the Clients settings tab, with the Reject Hostname Collisions toggle switched off" className="imagewrapper"/>
</p>

With the toggle on:

- No new peer gets a suffix. A peer whose DNS name is free registers with it; a peer whose DNS name another peer in the account already has fails to register, and no peer is created. The client reports `peer with hostname "laptop" is already registered`, stops retrying, and stays disconnected until it logs in again with a hostname whose DNS name is free, for example with `netbird up --hostname <name>`.
- Renaming a peer in the dashboard or through the API to a name whose DNS name another peer already has fails with the same error.
- Ephemeral peers follow the same rule, so they also lose the suffix they get by default.

Collisions are matched on the DNS name, not the raw hostname. To build it, NetBird takes the part of the hostname before the first dot, lowercases it, and replaces each run of characters that are not valid in DNS with a single `-` (non-ASCII characters are first converted to punycode). So `Laptop` and `laptop` collide, so do `my_laptop` and `my-laptop`, and so do `web.prod` and `web.staging`, which both become `web`.

Enabling the toggle does not touch existing peers: DNS names that already carry a suffix keep it, and a registered peer is not checked for collisions when it logs in again, even under a hostname another peer uses. The toggle only blocks DNS names that are already taken, so a peer that already has a suffixed name, such as `laptop-12-7`, doesn't block a new `laptop`.

Deleting a peer frees its name for the next registration, but it does not remove the suffix from a peer that already has one. To give that peer a DNS name without the suffix once the name is free, rename the peer to another name and then back. Saving the same name does not recompute it.

Keep the toggle off if your fleet registers machines with identical hostnames on purpose, such as autoscaled VMs or containers that join through a [setup key](/manage/peers/register-machines-using-setup-keys). The default suffix exists for that case, and with the toggle on every such machine after the first fails to join.

This setting is available on NetBird Cloud and on self-hosted management servers running v0.81.0 or later. In the API it is the `peer_hostname_collision_rejected` field of the [account settings](/ipa/resources/accounts).

## Agent Network-focused view

Accounts using [Agent Network](/agent-network) see an additional `Agent Network focused view` toggle. When enabled, the dashboard shows only the Agent Network-related sections and hides parts that are not relevant for it, such as Networks, DNS, and Reverse Proxy. Disable it to bring back the full dashboard.
