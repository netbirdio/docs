# Enforce NetBird Settings on Windows

On Windows, the NetBird client reads its MDM policy from one registry key, `HKLM\Software\Policies\NetBird`. Every value under that key becomes policy, whichever tool wrote it. This page shows how to get the values there with Microsoft Intune, Group Policy, a `.reg` file, or JumpCloud, and how to confirm they arrived.

What each key does, and how the client applies and locks a policy, is on the [MDM Integration](/client/mdm-integration) page. Read its [How the client applies a policy](/client/mdm-integration#how-the-client-applies-a-policy) section first if you have not.

We use the baseline policy from that page as the running example: Acme pins its laptops to its self-hosted server at `https://netbird.example.com:443`, makes settings read-only, and disables profiles. As a `.reg` file, the whole policy is:

```
Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\Software\Policies\NetBird]
"ManagementURL"="https://netbird.example.com:443"
"DisableUpdateSettings"=dword:00000001
"DisableProfiles"=dword:00000001
```

## Registry value types

Each key needs a value of the right registry type. Value names are matched without regard to case.

| Registry type | Value names |
| --- | --- |
| `REG_SZ` (string) | `ManagementURL`, `PreSharedKey`, `DebugBundleUploadURL`, `LocalMetricsAddress`, `SplitTunnelMode`, `SplitTunnelApps` |
| `REG_DWORD`, `0` or `1` (boolean) | `AllowRemoteJobs`, `AllowServerSSH`, `BlockInbound`, `DisableAdvancedView`, `DisableAutoConnect`, `DisableAutostart`, `DisableClientRoutes`, `DisableMetricsCollection`, `DisableNetworks`, `DisableProfiles`, `DisableServerRoutes`, `DisableUpdateSettings`, `EnableLocalMetrics`, `LazyConnection`, `RosenpassEnabled`, `RosenpassPermissive` |
| `REG_DWORD` (integer) | `WireguardPort`, for example `0x0000ca6c` for `51820` |

A boolean can also be a `REG_SZ` holding `true`/`false`, `1`/`0`, `yes`/`no`, or `on`/`off`. A string key stored with any type other than `REG_SZ` or `REG_EXPAND_SZ` is ignored: a `ManagementURL` stored as a `REG_DWORD`, for example, has no effect. The client reads `REG_SZ`, `REG_EXPAND_SZ`, `REG_DWORD`, `REG_QWORD`, and `REG_MULTI_SZ` values, and skips any other type with a warning in its log.

<Note>
**Standard users can read these values.** By default, every user on a Windows device can read `HKLM\Software\Policies`, so a `PreSharedKey` or `DebugBundleUploadURL` stored there is visible to them. Only administrators can change the values. An administrator on the device can always edit or delete the key, so give users standard accounts.
</Note>

## Choose a delivery channel

All four channels end in the same registry key. Pick the one that matches how your fleet is managed:

| Your fleet | Use |
| --- | --- |
| Cloud-managed with Intune | [Microsoft Intune with imported templates](#microsoft-intune-imported-templates) |
| Domain-joined, on-premises Active Directory | [Group Policy](#group-policy) |
| Managed with JumpCloud | [JumpCloud](#jump-cloud) |
| No MDM, or a quick test on one machine | [A `.reg` file](#a-reg-file) |

Download the templates and samples used below:

- <a href="/docs-static/files/netbird.admx" download>netbird.admx</a> and <a href="/docs-static/files/netbird.adml" download>netbird.adml</a>: the Group Policy templates, covering every key.
- <a href="/docs-static/files/netbird-policy.reg" download>netbird-policy.reg</a>: a sample `.reg` file that sets every key, including `PreSharedKey` and `DisableClientRoutes`, which cut a laptop off from most of the network. Delete every line you do not mean to pin before you use it.
- <a href="/docs-static/files/netbird-policy.reg.ps1" download>netbird-policy.reg.ps1</a>: the JumpCloud companion script.

In the Group Policy editor and in Intune, the templates show each key as a policy named after the key in plain words, such as **Management URL**, **Disable update settings**, or **Block inbound**, under **Computer Configuration → Administrative Templates → NetBird**.

### Microsoft Intune (imported templates)

This is the recommended channel for cloud-managed Windows fleets. It gives you the same policy editor as on-premises Group Policy.

1. In the Intune admin center, go to **Devices → Configuration → Import ADMX**. Upload `netbird.admx` together with `netbird.adml`, and wait until the status is **Available**.
2. Create a new configuration profile: **Templates → Imported Administrative templates**, then select **NetBird**.
3. Set the policies you want to pin. For Acme's baseline, enable **Management URL** with `https://netbird.example.com:443`, then enable **Disable update settings** and **Disable profiles**.
4. Assign the profile to your device group and save.

Devices pick up the policy at their next Intune sync, typically within 8 hours. To speed up a test device, trigger a sync from **Settings → Accounts → Access work or school → Info → Sync**. The client then applies the policy within a minute.

#### Custom OMA-URI

If you cannot use imported templates, you can push individual values with a custom OMA-URI profile under `./Device/Vendor/MSFT/Policy/ConfigOperations/ADMXInstall/...`, or with the Registry CSP at `./Device/Vendor/MSFT/Registry/HKEY_LOCAL_MACHINE/Software/Policies/NetBird/<ValueName>`. Imported templates are simpler and less error-prone, so prefer them.

### Group Policy

For domain-joined devices, follow [Deploying NetBird with Group Policy (GPO)](/manage/peers/mdm-deployment/windows-gpo-deployment). It walks through the Central Store, creating the policy GPO, installing the MSI silently, and scoping, end to end.

To test the templates on a single machine with the local Group Policy editor:

1. Copy `netbird.admx` to `C:\Windows\PolicyDefinitions\` and `netbird.adml` to `C:\Windows\PolicyDefinitions\en-US\`.
2. Open `gpedit.msc` and go to **Computer Configuration → Administrative Templates → NetBird**.
3. Open a policy, such as **Management URL**, set it to **Enabled**, enter the value, and click **OK**.
4. Run `gpupdate /force`.

### A `.reg` file

For a device without an MDM, or a quick test, carry the whole policy in one `.reg` file, such as Acme's baseline at the top of this page. Apply it from an elevated prompt:

```
reg import netbird-policy.reg
```

To build one from a reference machine that already has the policy you want, export the key:

```
reg export "HKLM\Software\Policies\NetBird" netbird-policy.reg /y
```

`reg import` adds and overwrites values, but never removes them. To take a key out of the policy, delete its value with `reg delete "HKLM\Software\Policies\NetBird" /v <ValueName> /f`.

### JumpCloud

NetBird ships a companion script for JumpCloud, <a href="/docs-static/files/netbird-policy.reg.ps1" download>netbird-policy.reg.ps1</a>, that applies a `.reg` file as the complete policy for the device.

1. In the JumpCloud admin console, go to **Device Management → Commands → +**.
2. Set **Type** to **Windows PowerShell** and **Run as** to **SYSTEM**.
3. Paste `netbird-policy.reg.ps1` into the command body, unchanged.
4. Attach your `.reg` file to the same command. JumpCloud copies attached files into the command's working directory before it runs the script.
5. Bind the command to the target device group and run it.

The script deletes the existing `HKLM\Software\Policies\NetBird` key before it imports the `.reg` file, so the file is the **complete** policy for the device: any key it does not contain is no longer pinned. To remove the whole policy, attach a `.reg` file that contains only the header line.

## Verify

On a target device, check that the values arrived:

```
reg query HKLM\Software\Policies\NetBird
```

Then check what the client is enforcing:

```
netbird debug config
```

The `mDMManagedFields` array in the output lists every key the client is enforcing. For Acme's baseline, it contains `disableProfiles`, `disableUpdateSettings`, and `managementURL`. The client log at `C:\ProgramData\Netbird\client.log` has an `MDM enrolled with N managed key(s): [...]` line on every reload. See [Verifying enforcement](/client/mdm-integration#verifying-enforcement) for more.

## Troubleshooting

**`reg query` shows no values.**
The delivery channel did not write them. For Group Policy, run `gpresult /h report.html` and look for errors on the NetBird GPO. For Intune, check the profile's device status in the admin center, and the sync status under **Settings → Accounts → Access work or school → Info**.

**The values are in the registry, but `mDMManagedFields` does not list them.**
Look for `MDM ignoring unknown registry value` in the client log: the value name does not match a key. Then look for `MDM ignoring unsupported registry value type`: the value has a registry type the client does not read.

**A key is listed in `mDMManagedFields`, but the setting did not change.**
The value has the wrong type for its key, such as a `ManagementURL` stored as a `REG_DWORD`. Check it against [Registry value types](#registry-value-types).

**A key stays pinned after you removed it from a `.reg` file.**
`reg import` does not delete values. Delete the value with `reg delete`, or use the [JumpCloud](#jump-cloud) script, which replaces the whole key.

For problems that look the same on every platform, see [Troubleshooting](/client/mdm-integration#troubleshooting) on the MDM Integration page.

## Recap

- The client reads `HKLM\Software\Policies\NetBird`; anything written there is policy.
- Acme's baseline is three values: `ManagementURL` as a `REG_SZ`, and `DisableUpdateSettings` and `DisableProfiles` as `REG_DWORD` `1`.
- Use imported templates in Intune, Group Policy on a domain, the companion script on JumpCloud, or a `.reg` file for a test.
- Confirm with `reg query`, then `netbird debug config`.
